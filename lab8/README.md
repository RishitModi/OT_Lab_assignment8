## Project Overview

Assignment 8 "Optimize Anything" of the course Optimization Techniques covers ten compulsory tracks A to J. Each track defines an optimization problem, establishes a baseline, implements a fair set of comparison methods, and checks correctness by running in-process assertions and pytest unit tests. All code was generated by AI from prompts (see the AI Tools Register below and `prompts/`); all programs were run and checked by the student.

## Setup Instructions

### Prerequisites
- Python 3.12 or newer
- Git

### Environment Setup

1. **Clone the repository and enter the lab8 folder:**
   ```powershell
   git clone <repo-url>
   cd optimize-anything-assignment8\lab8
   ```

2. **Create and activate a virtual environment (PowerShell):**
   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

3. **Install dependencies:**
   ```powershell
   pip install -r requirements.txt
   ```

> [!NOTE]
> On one Windows machine `pandas` could not be imported inside the virtual environment because of an Application Control policy. Tracks E, F, and H were therefore run with the system Python (3.15.1). They work with any interpreter that has `numpy`, `scipy`, `matplotlib`, and `pandas`.

> [!NOTE]
> Track G requires WSL2 (Ubuntu) with the packages `build-essential`, `gcc-multilib`, `qemu-system-x86`, `git`, and `perl`. Clone the xv6 source into `tracks/track_g_xv6/xv6-public`:
> ```bash
> git clone https://github.com/mit-pdos/xv6-public.git tracks/track_g_xv6/xv6-public
> ```
> That folder is **not committed**. The committed patch is `tracks/track_g_xv6/patches/lottery_scheduler.diff`. See `tracks/track_g_xv6/scripts/README_RUN.md` for full build and run instructions.

## Dependencies

All runtime dependencies are listed in `requirements.txt` (no pinned versions):

| Package | Used for |
| :--- | :--- |
| `numpy` | All numerical work: arrays, linear algebra, random number generation |

| `pytest` | Unit and smoke tests for all tracks |

**Not in `requirements.txt`:**
- The quantum circuit simulator, the compiler, the xv6 kernel programs, and the DBMS data generator are all implemented in this repository.
- SQLite comes with Python and is used in Track H.
- QEMU is needed only for Track G (kernel simulation in WSL2).

## How to Run Each Track

All commands are run from the repository root (`lab8/`). Most experiment scripts support `--quick` for a reduced run (under 60 s). Tests for each track must be run separately — running all tests in a single `pytest` command can cause module-name collisions between tracks. The Track D test suite may stall due to the work-stealing simulator loop (see Failure Log case 16).

| Track | Command | Typical run time | Output |
| :--- | :--- | :--- | :--- |
| **A** | `python tracks/track_a_continuous/run_all.py [--quick]` | ~5 min full; <30 s quick | `results/track_a/SUMMARY.md` and figures |
| **B** | `python tracks/track_b_discrete/run_all.py [--quick]`<br>`python tracks/track_b_discrete/b3_penalty_k.py` | see track README | `results/track_b/SUMMARY.md` and figures |
| **C** | `python tracks/track_c_quantum_opt/run_all.py [--quick]`<br>(requires `results/track_b/qubo_instances.json` from Track B) | see track README | `results/track_c/SUMMARY.md` and figures |
| **D** | `python tracks/track_d_submodular_parallel_distributed/run_all.py --only D1 D3 D4 [--quick]`<br>(D2 is known not to complete, see Failure Log case 16) | see track README | `results/track_d/SUMMARY.md` and figures |
| **E** | `python tracks/track_e_case_study/run_all.py [--quick]` | see track README | `results/track_e/SUMMARY.md` and figures |
| **F** | `python tracks/track_f_compiler/run_all.py` | see track README | `results/track_f/SUMMARY.md` and figures |
| **G** | See `tracks/track_g_xv6/scripts/README_RUN.md` | see track README | `results/track_g/` |
| **H** | `python tracks/track_h_dbms/run_all.py [--quick] [--sf 0.05]` | see track README | `results/track_h/SUMMARY.md` and figures |
| **I** | `python tracks/track_i_quantum_algos_qml/run_all.py [--quick]` | see track README | `results/track_i/SUMMARY.md` and figures |
| **J** | `python tracks/track_j_software_eng/run_all.py [--quick]` | see track README | `results/track_j/SUMMARY.md` and figures |
| **Tool comparison** | `python tool_comparison/verify.py tool_comparison/<tool>/solution.py` | <1 s | pass/fail + speed test |

**Unit tests (run each track separately):**
```bash
python -m pytest tracks/<track_folder>/tests -q
```

## Reproducibility

- **Seeds:** Seeded random-number generators throughout; base seed `42`. Instance-level seeds are recorded in each `results/<track>/SUMMARY.md`.
- **Versions and hardware:**
  - OS: Windows 11, 18 logical cores
  - Python: 3.12.10 (virtual environment) / 3.15.1 (system, used for Tracks E, F, H)
  - NumPy: 2.5.4 (venv) / 2.5.2 (system)
  - SciPy: 1.18.1
  - scikit-learn: 1.9.1
  - SQLite: 3.53.4 (bundled with Python)
- **Notes:**
  - Results for Tracks E and J come from the `--quick` configuration.
  - Timings are single-machine wall-clock measurements and are not used for ranking between tracks.
  - No real quantum hardware was used anywhere; all quantum algorithms are simulated on a self-written NumPy statevector simulator.

## Known Gaps

- **D2 (parallel scaling):** The work-stealing scheduling simulator contains a non-terminating loop; the experiment was not completed and no measured speedup or efficiency is reported. See Failure Log case 16.
- **Track A:** The noisy-objective experiment (exp4b) and the convergence-rate fit (exp2a slope) are invalid and excluded from the report. See Failure Log cases 7 and 8.
- **Track J:** Mutation testing did not complete on the full test universe; the fault-detection cost of test minimisation is not measured. See Failure Log cases 25 and 26.
- **Track I:** The run deviates from the specification (one QPE phase only, Shor for N = 15 and 21 only, no classical simulated-annealing baseline in I3, no comparison table produced). See Failure Log case 23.

Coverage of Chapter 6 areas is tracked in [CHECKLIST.md](CHECKLIST.md). All bugs and AI-introduced errors are recorded in [FAILURE_LOG.md](FAILURE_LOG.md).

## Commit Convention
To maintain attribution and transparent traceability between manual edits and AI generation:
- AI-assisted commits must be prefixed with `[AI:tool-name]`, e.g.:
  ```
  [AI:antigravity] Implement AdaGrad and RMSProp optimizers in Track A
  ```
- Manual student edits must be prefixed with `[MANUAL]`, e.g.:
  ```
  [MANUAL] Correct boundary condition in Branch-and-Bound pruning
  ```
